# 可维护的产品与 BOM 数据包

低空演示包在 `low-altitude-demo/catalog.json`。它是业务资料，不是 Skill，也不包含可执行脚本。当前包含23个产品、23份BOM、8条公开资料来源。解决方案属于具体客户项目，由客户需求驱动自由组合，不存入产品库。公司名称“凌空”、公司产品与组合均为虚构；厂商设备是公开资料参考。所有性能承诺、供货配置和项目选型仍需实际验证。

## 维护入口

- “产品目录”：维护能力、限制、产品类型、交付来源、供给状态、适配条件、交付物与数量口径。归档保留历史引用，停止新匹配；勾选显示已归档后可编辑并重新启用。
- “产品 BOM”：维护单产品组成用量、组成项来源、目录产品引用、选配条件和版本。普通组成项不必成为可售产品；可复用组合可以引用目录产品并继续展开。
- “数据包维护”：导出完整 JSON。批量维护或替换行业数据后，先导入预览再应用。支持引用/单位/循环校验和人工修改保护。导出包包含归档的旧数据，便于保留关联。

首次启动安装默认包。后续重启不重置目录，也不自动应用仓库 JSON 的变化。升级 JSON 后，应通过页面导入；预览按“上次导入、本地当前、此次数据包”三方比较。未改动条目可以更新，本地修改或本地移除的条目保留并列出冲突。上游移除且本地未修改的产品只归档；BOM可移除，历史项目快照保留。导入预览过期则拒绝应用。

页面编辑BOM时形成目录修订；内容变化且版本未变时，自动增加补丁版本。产品编辑、导入和BOM变更保存目录修订。重复导入相同内容不制造新修订。数据库 `catalog_revisions` 保存全量版本，`catalog_imports` 保存三方比较基线。

旧版schema 1数据包仍可导入，但其中的解决方案模板会忽略并提示；schema 2拒绝解决方案字段。已有目录启动时迁移为仅包含产品/BOM的结构，原有目录修订和客户项目历史快照保留。原项目的方案名称、说明、需求与产品关联继续可用，旧模板引用不再参与生成。

## 字段约定

- 顶层：`schema_version: 2`、稳定 `id`、业务 `version`、`name`、`description`。
- `references[]`：`id`、标题、HTTPS URL、核对日期。产品通过 `metadata.reference_ids`引用来源。
- `products[]`：稳定编号及原有产品字段；`metadata` 中维护 `kind`、`delivery_source`、`availability`、`data_kind`、`quantity_policy`、`active`、`requires_validation`、`compatibility[]`、`deliverables[]`、`reference_ids[]`。
- `boms[]`：稳定编号、`product_ref`、版本、`kind`、`basis`、`lines[]`。每行包括编号、名称、`qty`、单位、来源、可选的关联产品、`optional`、选配条件和备注。
- BOM `qty` 是每一单位父产品的组成用量；`null` 表示待确认。关联产品的单位必须与行单位相同。支持嵌套，禁止循环。可选项默认未选配；当前项目页面不提供选配决策编辑，有选配需求时先维护经确认的产品配置版本。
- 厂商公开参考产品只能维护“模拟交付配置”，不伪造厂商内部制造 BOM。自研原型给出“模拟产品组成”，部件数量仅用于工程配置示范。软件 BOM 描述组成模块，不能额外重复计价。
- 产品来源为自有产品、外采、自研、服务；供给状态独立维护。外采和自研产品同样可以被 PBS 引用并展开 BOM。`requires_validation` 控制匹配时的专项验证提示，避免依赖供给状态的显示文案判断；未验证能力不能视为现成覆盖。

## 数量规则

默认所有新产品采用 `quantity_policy: unknown`。只有明确按单套许可交付的软件可选 `single_license`；不能因为单位是“套”就推定数量为 1。外采软件许可期限与节点数默认待确认。

`sizing.params` 声明参数名称、单位、单位别名、原文关键词；`sizing.rules` 每条用产品编号绑定一个已确认参数（`id/name/product_ref/param/unit`）。本版数据包不支持隐式覆盖面积推算或任意代码/公式。未来若要新增计量策略，应扩展通用引擎契约，而非把行业设备编号写进引擎。

BOM 展开用量 = 父产品数量 × 单产品用量；任一未知则结果未知，不把空值当 0 或 1。PBS 数量单位与产品计量单位不同也保留待确认。组件不是新的 PBS 采购项；发现组件也作为独立 PBS 产品出现时提示核对重复范围。

旧版规则只为已经使用它的旧项目保留解释，禁止触发新的旧设备补项；新目录关闭旧版覆盖半径、备机比例、默认接口人天等假设。旧项目受影响项标记待复核。

## 项目使用与代码边界

在项目PBS页新增项目方案，至少关联一个客户场景或原始需求，自由选择承接需求的PBS产品项，填写选型理由、交付范围和待确认事项。同一产品库可以支撑不同客户的不同组合，项目编辑不改变共享产品目录。模型只看到当前项目方案和当前客户需求，不接收全局方案模板。方案保存后仍为草稿。

“保存方案与 BOM 快照”固定当时的目录修订、方案、产品、BOM和数量。目录更新或项目输入变化会提示快照待复核，但不会替换已存内容；重新保存可刷新当前快照。共享同一个 PBS 项的多个方案只展示多处关联，导出 BOM 按唯一 PBS 项列出。项目的两个不同 PBS 项引用同一产品仍分别保留，避免擅自合并不同交付范围。

Excel 新增“解决方案产品关系”“产品BOM组成”两张表。有已存快照时导出该快照，并明确是否待复核；没有快照时导出当前展开草稿。PBS 清单本身仍为当前项目内容，因此旧快照待复核时应先重新核对再对外交付。

- `engine/catalog.mjs`：纯校验、稳定摘要、嵌套 BOM 展开和数量策略；不依赖数据库或低空数据。
- `server/catalog.mjs`：共享产品目录版本、导入合并、运行配置适配。
- `server/project-solutions.mjs`：客户项目方案、自由组合、项目关联与BOM快照；依赖产品目录读取，不向产品库写入方案。
- `catalogs/*/catalog.json`：行业业务资料和来源。
- `web/pages/products.js`、`products-list.js`：目录维护。
- `web/pages/tabs/project-catalog.js`：项目三层关联与快照展示。
- `test/catalog.test.mjs`：独立离线验证，不调用付费模型或厂商接口。

当前目录为单一公司目录。不同数据包导入采用保留本地内容的合并策略；彻底切换行业时需要在产品页归档旧行业产品。尚未提供多租户、多目录并行、价格管理、库存采购或PLM工程审批。
