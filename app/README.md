# PBS 智能拆解系统

给一段客户需求（用户描述、会议纪要、招标文件），通过对话把它拆成 PBS 清单，并逐项匹配产品库：用哪个产品的哪项能力，或被哪条限制挡住、需要外采或自研。

## 启动

```bash
cd app
npm install     # vue、element-plus（前端）、exceljs、mammoth、pdf-parse
npm start       # http://127.0.0.1:8765/
npm test        # 离线测试，不调用模型
npm run check   # 提交前执行：ESLint + 前端模板编译检查 + 测试
```

要求 Node ≥ 22.13（使用内置 `node:sqlite`）。模型配置读仓库根目录 `.env`，从 `.env.example` 复制后填写：`BAI_API_KEY`、`BAI_BASE_URL`；`APP_MODEL` 指定对话和拆解用的模型（默认 `gpt-5.4-mini`）；`EMBED_MODEL` 指定向量模型（默认 `text-embedding-3-small`）。

向量接口不可用时，系统自动退回关键词检索，页面右上角会显示当前检索模式。`APP_EMBED=off` 可强制关闭向量检索，`APP_LLM_CACHE=on` 会缓存相同提示词的模型结果（演示彩排用，默认关闭）。

## 怎么用

1. **产品库**：新增产品，或下载 Excel 模板批量导入，或上传产品手册（模型整理出能力和限制，你确认后入库）。首次启动安装独立低空示例包：23 个产品、23 份 BOM，旧模拟产品归档并保留历史引用。
2. **新建项目**，进入项目页：左边对话，右边是工作区（材料、需求、场景需求、澄清、PBS、导出）。
3. 在对话里粘贴客户材料或拖入文件，然后说“抽取需求”“生成 PBS”“把机场改成 12 个”“为什么要自研车牌识别”“客户确认了 12 个机场”。右边工作区会自动切到对应结果，也可以直接在表格里编辑。
4. 在“场景需求”生成草稿：查看业务目标、活动、原文依据和未解决问题；可以修改、合并、拆分或归档。保存编辑后仍为待确认，审阅后再单独确认。
5. 在“原始需求去向”检查场景关联、跨场景约束、交付服务、商务资质、范围外和待归类事项。一个条款可以对应多项需求，一个需求也可以支撑多个场景。
6. 在“澄清”录入客户答复并选择应用变更。涉及正式标书的潜在冲突需要记录处理依据；场景与相关 PBS 会标记复核。
7. 生成 PBS，再沿场景和原始需求核对产品依据与数量。在 PBS 页按客户场景组织“解决方案 → 产品 → BOM”，保存版本快照。导出 Excel 包含需求/场景追溯、解决方案产品关系与产品 BOM 组成，共九张表。

## 设计要点

- **对话驱动，代码把关**：模型把你的话转成一组固定的操作，代码逐个校验目标是否存在、参数是否合法，再通过和工作区同一套业务逻辑执行。删除类操作要在卡片上确认。
- **人工修改优先**：你确认、修改、新增的需求，手填的数量，改过的 PBS 项，重新抽取或重新生成时都不会被覆盖。
- **数量不由模型拍脑袋**：只来自测算规则、原文数字、人工填写或显式声明的单套软件许可，其余一律“待估”。
- **匹配有依据**：声称的产品能力、被挡住的限制，必须在产品库里真实存在，否则丢弃；检索到的手册片段会展示在证据卡里。
- **稳定来源与版本**：重抽取保留历史需求编号；材料移除后保留原文快照；索引重建保留产品证据编号，旧资料仍可查看。被替代的场景保留版本和替代关系。
- **变更只影响关联结果**：需求、场景、约束或产品证据变化后，相关 PBS 取消确认并标记复核。模型执行期间如果依据被修改，旧输出不能覆盖新结果。
- **场景描述与未知事项分开**：确认场景描述不会自动关闭其问题。有未解决的场景问题时仍可生成草稿，但相关 PBS 需要先完成复核再确认。
- **客户答复闭环**：录入答复后，模型先分析会改变什么，你勾选采纳后才生效；受影响的数量自动重算并标记“待复核”。

## 目录

```
engine/   拆解引擎：切分、抽取、匹配、测算、审核（不依赖数据库和 HTTP）
lib/      B.AI 模型网关客户端（读取 .env、代理、重试）
server/   node:sqlite、检索、后台任务、业务逻辑、对话控制、HTTP 接口
web/      不打包的 Vue 3 + Element Plus 前端
catalogs/ 独立行业示例包及维护契约（产品、BOM、来源、计量参数）
seed/     兼容旧版本的初始数据：产品、测算规则、PBS 模板、检查清单、历史项目、示例输入、产品手册
scripts/  开发辅助脚本（前端模板编译检查）
data/     运行数据（SQLite），不入库；删掉可恢复初始状态
test/     单元测试与假模型走完整旅程的集成测试，全部离线
```

客户解决方案在项目内根据需求自由组合。产品与BOM在产品库独立维护，也可导出/导入JSON数据包；项目方案、行业数据与通用引擎分离。新目录使用数据包中的明确参数计量，旧版 seed 规则仅保留已有项目引用。PBS 分类模板、检查清单仍位于 `seed/config/*.json`。详细维护方式见 [catalogs/README.md](catalogs/README.md)。

## 场景需求开发与验证

场景分析在 `engine/scenario.mjs`，独立持久化和版本操作在 `server/scenarios.mjs`，页面在 `web/pages/tabs/scenarios.js`。数据库启动时增量迁移；旧项目的数据与人工成果保留，旧场景元数据不会推定为已确认的新场景。

场景生成最多进行一次结构修正；引用不存在、非法关联或无依据数字会让生成失败，并保留之前的结果。工程校验不能替代业务人员对语义和场景粒度的审阅。

`test/scenarios.test.mjs` 覆盖新流程、迁移、来源失效、合并拆分、并发版本、澄清应用、索引证据和实际 Excel 工作簿。模型部分使用离线脚本响应；真实模型质量应使用 `docs/superpowers/specs/2026-10-20-scenario-requirements-cases.json` 的三种材料案例另外评测。
