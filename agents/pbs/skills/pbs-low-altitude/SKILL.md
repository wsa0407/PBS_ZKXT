## 使用方式

在已有客户场景和材料上发现与交付有关的专业缺口。以下是可选择的核查维度，不是自动新增功能、产品或整套“低空底座”的模板。先看任务类型，再看相关条件；泛行业规则留在其他技能，本技能可单独替换维护。

## 按业务目标核查

| 业务问题 | 有价值的核查方向 |
| --- | --- |
| 巡查/应急任务 | 区域、对象、触发或频次、任务结果、人员职责；是否只发现/告警，是否要求后续处置 |
| 飞行器与载荷 | 载荷类型、目标数据、适用工况、挂载/供电/通信兼容；能力指标对应实际型号和版本 |
| 机库与站点 | 客户现有资产、点位条件、供电网络、起降环境、值守维护与作业周转；未明确点位不推算机库数量 |
| 平台集成 | 任务、设备状态、视频、媒体文件、告警和业务工单各自的接口及责任，不把视频观看当飞行控制能力 |
| 数据成果 | 视频流、照片、轨迹、地图及分析结果的时空基准、存储归属、保留周期与交付标准 |
| 运行异常 | 电量、通信、定位、天气和区域限制等是否影响当前承诺；核对产品已有机制及需要人工处理的部分 |
| 低空感知 | 探测、识别、定位、跟踪、告警分别响应什么要求；指标对应目标和环境，不能以一个能力推断全部满足 |

## 防止专业概念误用

- 飞机数量、同时作业数量、机库数量、站点数量、视频并发与算法通道分别核对。覆盖面积或单次续航不能单独决定采购数量。
- 标称续航、最大航程、载荷能力与项目实际任务工况不同；没有工况资料不承诺任务覆盖或频次。提出需要验证的条件，不用经验默认风速、距离或电量门槛。
- 热成像、可见光、算法与测绘成果能力分别核实；检出某类目标不等于已满足识别准确率或测量精度。
- 标准协议、厂商云接口与本地部署支持分别核实；公开开发文档不是公司目录产品已集成或项目已兼容的证据。
- 感知、告警与处置设备分别确定范围；不能因出现“反制”字样就自行增加未提出的设备或功能。涉及运行许可、资质或适用规则时依据项目所在地、时点和提供的正式材料，由有权限人员核实，不把网上示例当通用合规结论。

## 输出与工具

给出与当前客户目标有关的遗漏或边界问题，关联真实条款/需求。区分客户已提出、产品使用前提、专家建议和仍未知，不能将这张核查表批量转成需求或采购清单。

材料仅提到“机库点位数量待勘察”，还不足以认定本轮必须采购机库：先核对是否为客户已有资产、交付责任以及是否进入已确认需求范围。未建立需求或未纳入本轮确认时，提出范围核对建议，不能直接要求补一个 PBS 采购项。已明确“推送已有工单系统、不新建工单平台”时保留这项边界，只追问未提供的接口和联调条件，不再把是否负责完整工单闭环说成未知。

交付前逐项反查疑问：若材料已写“推送异常”和“视频保留 30 天”，未知的是接口具体约定以及其他数据类型是否有保留要求，不能再称推送对象和视频保留期均未明确。将多个数据类型混写成一条未知事项，可能掩盖已有事实，应拆开说明。

原文问题回查材料，产品事实用 read_product 及来源核对，客户决策用 pbs-clarification，数量用 pbs-capacity-sizing，系统责任用 pbs-interface-boundaries。按实际角色权限保存；本技能不调用设备、不执行飞行或处置操作。

## 方法来源与时效

核查维度参考 [DJI Cloud API](https://developer.dji.com/cloud-api/) 对云平台/设备接入的说明，以及 [PX4 安全配置文档](https://docs.px4.io/main/en/config/safety) 中电量、链路、定位和区域等异常类别。资料查阅于 2026-10-21，仅用于组织问题；不复制默认参数，不推定其他品牌或版本拥有相同能力。实际选型以本项目当前可回读产品资料为准。
