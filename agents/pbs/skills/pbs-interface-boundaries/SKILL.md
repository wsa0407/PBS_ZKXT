## 输入与范围

读取相关需求、场景、原文及候选产品的接口限制。先识别“谁与谁交换什么、为哪个客户目标服务”，再分析接口；接口名称和协议相同不代表已兼容。只展开与本次任务有关的接口，不为每个项目生成完整系统设计。

## 边界检查

对每个实际接口区分已知、推断和未知，按需检查：

| 方面 | 要明确的内容 |
| --- | --- |
| 两端与责任 | 提供方、接收方、客户已有资产、我方/第三方交付与运维责任 |
| 业务语义 | 传递告警、视频、轨迹、任务还是控制指令；单向推送、回执或业务闭环 |
| 数据约定 | 真实标识、字段与单位、时间基准、坐标/高程基准及数据归属 |
| 服务条件 | 协议与版本、鉴权、网络区域、部署环境、并发/吞吐及失败反馈 |
| 联调验收 | 接口文档、测试环境、双方负责人、可用时间、成功判据与证据 |

这些是核查维度，不是自动新增的客户需求。缺少某项只有在影响当前决策时才提出澄清；不能为补齐表格而编造协议、服务等级或责任人。

## 映射到场景与 PBS

- 客户已有工单系统且只要求推送告警，不等于采购新的工单平台，也不等于我方负责派单到关闭的全流程。
- 已经明确“不新建工单平台、只推送”的材料，应固定这一已知边界，澄清尚未明确的回执语义、数据约定或联调责任，不能重复询问是否需要新建完整闭环。
- 客户提供服务器并不代表无需部署适配或性能核对；部署条件与采购交付分别说明。未经确认不新增一套服务器。
- 设备数量、接口端点数、消息类型数与接口服务工作量不能互相替代。尚无计量依据时保留数量未知。
- 产品声称支持标准协议只是候选线索，仍核对具体版本、语义、授权及使用条件。没有试验结果时不能宣称联调通过。

交付接口边界说明、未知事项及关联需求/场景；范围变化使用 pbs-change-impact。获授权时用 submit_scenarios 的 boundaries、submit_pbs 的 spec/basis 或 submit_questions 保存相应内容；不得向 schema 添加自创 interface 字段。咨询模式提交只读答复；当前没有独立接口台账写入工具。

## 方法来源

参考 [NASA Interface Management](https://www.nasa.gov/reference/6-3-interface-management/) 对接口两端、责任和变更的关注。表中低空平台对接检查及现有工具映射为本项目适配，不代表本项目应采用 NASA 的审批组织。
