# 仓库清理与一致性核查

日期：2026-10-21。

## 范围和结果

核查了 HTTP 入口、协作调度、角色工具、人工确认、业务保存、共享语义、运行时、测试及当前文档。
当前业务生成统一走角色认领与 dsh 执行；保留人的工作区编辑与历史数据兼容。

| 发现 | 处理 |
| --- | --- |
| 旧单 Agent 执行器仍可注册全部业务工具 | 删除 `agent-chat.mjs` 和 unrestricted `runAgent`，角色执行必须提供有效角色 |
| `/chat` 仍能接收旧 JSON 修改指令 | 只接受单个生成意图兼容；混合批次及可执行修改返回 400 |
| 材料结束后由代码固定交接需求理解 | 移除自动交接；保留认领、咨询与明确人工确认的实际活动调度 |
| 旧需求/能力/场景/PBS 批量生成器和修复循环与工具式写入并存 | 删除无调用的生成、缓存、补漏、批处理分支；保留当前工具共用的确定性校验 |
| 聊天接口仍计算已移除的快捷建议 | 删除建议生成与返回字段 |
| 服务端从页面目录导入状态和展示语义 | 提取到 `app/shared/`，服务端与浏览器共用，增加静态资源路由 |
| PBS 保存自身成果的回执撤销需求理解确认 | 只保留真正影响理解范围的失效机制；PBS 自身成果调整保留有效确认 |
| 单项重新匹配可绕过人工确认 | 分析前后、建议采纳时检查确认版本和范围，并将候选需求/场景限定在批准范围内 |
| ★/▲ 被直接转换为“必须” | 将要求强度与来源标记分开；重点审阅继续保留 |
| 手册/答复等受限分析加载业务专家指令 | 独立分析身份，无业务 Skills 与业务写入工具 |
| 全仓检查只覆盖 app，历史测试仍调用旧路径 | ESLint 扩展至 app/agents/runtime；新增依赖、循环、角色工具、Skill 元数据检查；核心旅程改走当前 HTTP 协作入口 |
| 历史方案和 README 与现行行为冲突 | 新增根目录 `AGENTS.md`、架构说明、文档索引，历史设计明确标识 |

`app/engine/extract.mjs` 的剩余纯需求规则改名为 `requirements.mjs`。
旧 `engine/capability.mjs`、`engine/llm.mjs`、直接 chat completion 包装器及对应退休测试已删除。
`createHarnessLlm` 继续提供受限结构化分析，不是业务任务的另一套 Agent 入口。

## 保留内容

没有删除数据库迁移、已存项目、原文引用、人工修改、历史聊天卡片、旧能力记录及旧产品/规则引用。
`agent_runs` 和 `scenario_runs` 等历史表继续可读；旧能力 CRUD 仅供历史兼容。
`output/` 是用户本地文件，不属于本次清理。真实凭据、数据库和会话不纳入提交。

## 验证

`npm run check --prefix app` 已通过：全仓 ESLint、70 个模块的依赖边界/循环检查、25 个工具与 15 个共享 Skill 元数据、Vue 模板编译及 129 项离线测试，无失败或跳过。
核心验证涉及材料→需求理解→明确人工确认→PBS→导出，以及错误恢复、会话、取消、版本、幂等、角色权限和范围失效。
旧测试中数据库版本和导出 sheet 数的过期断言已随当前 schema/导出契约修正。

本地 8876 服务在无运行任务时完成更新，`/api/meta` 与四个共享模块地址返回正常。
更新前后核对项目、材料、需求和 PBS 项行数一致（3 / 5 / 83 / 27）；未对现有业务数据执行清理迁移。

本次未调用付费真实模型，也未进行浏览器视觉验收；离线测试不证明实际大标书的理解质量。
`verify-harness.mjs --live` 现在只使用临时数据库与合成材料；额外的
`--approve-test-scope` 仅批准该合成范围。

## 仍存在的限制

- 专家活动顺序调度，咨询方向为 PBS→理解/材料、理解→材料；完整双向与并行协作还需队列及循环依赖设计。
- 咨询答复的事实引用目前只接受项目材料，产品依据引用需扩展契约。
- 静态架构检查覆盖字面量相对导入及声明契约，不等于穷举所有动态执行与模型行为。
- 公司工作台迁移仍需实现工具权限、收件持久化、人工确认、幂等、版本、RAG 和会话等宿主契约；复制 Markdown 不足以替代这些服务。

以上限制已与 Agent 包及当前架构文档同步，未通过提示词宣称为已实现能力。
