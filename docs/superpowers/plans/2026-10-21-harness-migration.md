# PBS Harness 重构实施记录

依据：已确认的 `../specs/2026-10-21-deepseek-harness-migration-design.md`。

目标：现有界面接入官方 dsh；可迁移 PBS Agent 包独立于本地宿主和 RAG 实现。

## 交付顺序

1. 固定安装 dsh/SDK 0.2.1-rc.2，验证实际发布包的启动与配置接口。
2. 建立 Agent 包：指令、Skills、工具契约、验收样本。通用 loop 使用官方实现。
3. 实现本地证据、业务草稿、产品与成果服务适配器；建立项目隔离、幂等和版本检查。
4. 接入 MCP 与 dsh 本地宿主，验证真实模型工具错误后的纠正行为及会话恢复。
5. 接入聊天与业务分析入口，展示可核对的执行进度与成果，保护人工修改。
6. 完成离线业务回归、真实 dsh 组合验证和前端验证，提交实现及实际限制。

以上本地实现步骤已完成。详细结果见[实施验收记录](../specs/2026-10-21-harness-migration-validation.md)：124项自动检查、真实模型工具纠错与持久会话恢复、完整合成案例及页面停止/继续。公司宿主联调与完整112页标书的性能验收仍另行开展。

## 验证原则

- 先验证实际发布包；不根据 master 文档假定接口可用。
- 真实模型验证使用合成资料或公开招标文件，配置中不保存密钥。
- 不把模型说完成、运行时 idle 或工具调用成功等同于业务验收通过。
- 工具契约与本地适配器分开；同一 Agent 包可绑定契约兼容的公司服务。
- 已通过的检查仅在代码变化或新证据需要时重跑。
