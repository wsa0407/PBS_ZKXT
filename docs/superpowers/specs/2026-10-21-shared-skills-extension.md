# PBS 共享技能扩展：依据、设计与验收

用户已授权分析、检索并直接把关键技能写入仓库，继续沿用三个独立角色、共享技能目录、按问题选择方法的设计。本轮增加九项技能，总数从六项扩展到十五项。

## 为什么补这些能力

原六项覆盖材料拆解、场景、产品、证据、澄清与协作，但复杂项目中仍有不同性质的判断：材料是否完整、条目表达是否准确、系统责任归谁、怎样验收、数量怎样计量、备选怎样比较、关联是否实质覆盖，以及补充材料改变了什么。

选用九个按问题触发的技能，而非把所有判断继续堆进一个产品技能；也不把每个字段拆成单独技能。每个新增技能具备明确输入、判断要点、交付与权限边界。低空核查单独维护，通用角色只在任务涉及该领域时选用。

| 新增技能 | 当前关键缺口 | 方法边界 |
| --- | --- | --- |
| pbs-document-map | 多附件、续表、版本关联与解析缺损 | 导航及范围核查，不增加 OCR 或图片识别能力 |
| pbs-requirement-quality | 歧义、复合条目、重复、冲突及过度推断 | 检查需求自身，不代替产品测试或人工确认 |
| pbs-interface-boundaries | 既有系统、对接语义、交付和联调责任 | 分析实际边界，不自动购买客户已有系统 |
| pbs-acceptance | 指标工况与可核验条件缺失 | 验收条件草案，不宣称执行测试或验收通过 |
| pbs-capacity-sizing | 并发、设备、存储、许可及 BOM 混算 | 区分原文数量、条件计算与系统可接受的测算依据 |
| pbs-option-analysis | 自有、自研、外采与集成方案取舍 | 按真实约束比较，不编造权重、报价或交期 |
| pbs-traceability | 有关联但不满足、漏项、无依据扩展 | 核对实质对应，不用关联率冒充满足率 |
| pbs-change-impact | 补充材料与旧确认范围的连带影响 | 提出差异，遵守现有确认包及写入屏障 |
| pbs-low-altitude | 无人机、机库、感知、平台之间的专业遗漏 | 按客户业务核查，不把专业清单变成默认采购范围 |

## 加载、迁移和权限

所有新技能放在 agents/pbs/skills 的直接子目录，使用 name、description frontmatter。原有 pbsPreset 为三个角色挂载同一目录，因此无需新增角色技能白名单或改变权限。共用 AGENTS.md 改为以运行时目录为准，三份角色说明仅提供问题导向的选用提示。

当前业务 Agent 没有网页、shell 和任意文件读取权限，所以技能正文自包含，外部链接仅供维护者查证。没有添加需要这些权限才能执行的辅助脚本或 references 依赖。新技能提供方法，不授予 OCR、独立接口台账、验收执行、持久追溯矩阵或设备操作能力。

分析建议应进入现有成果字段、咨询答复、变更建议或本次记录；未存在的字段和 API 不得伪造。业务写入仍受角色、活动模式、确认范围和版本约束。当前自动交接和有限咨询方向等运行机制差距仍见上一轮审查，本轮没有通过新增 Skill 宣称解决这些问题。

当前 watch=false：后续宿主激活发现新目录，已经运行中的目录不保证即时更新。无需重启整个业务服务；新启动或恢复的角色活动会重新挂载。

## 验收范围

1. 使用 skill-creator 的 quick_validate.py 检查十五个技能的 frontmatter、命名和未完成模板。
2. 使用当前安装的官方 dsh-skill-filesystem 及真实 preset 配置，逐角色发现并加载全部技能，核对模型可调用性。
3. 六项既有协作核心测试保护人工确认、写入边界、恢复及数量范围；不增加 UI 快照或全量回归。
4. 以 agents/pbs/evals/skill-cases.json 的三个合成只读案例观察实际模型：材料质量、边界变更、PBS 数量与备选。expected_review 不发送给模型，评估使用真实 skill 工具调用记录与最终业务答复；不读取内部推理。

合成案例只能证明这些输入下观察到的技能选择和判断，不能代表所有技能在生产项目的完整正确率。当前只读验收不检查新成果持久化、不执行真实飞行、不修改用户项目。

## 已执行结果与实际限制

| 验证 | 结果 |
| --- | --- |
| 技能格式 | 十五个 SKILL.md 均通过校验 |
| 官方提供方发现/加载 | 三个角色各十五项，共四十五次加载，全部模型可调用，无解析警告 |
| 现有协作核心回归 | 六项通过；没有修改宿主调度与写权限 |
| 真实模型选用 | dsh 0.2.1-rc.2，经 BAI 调用当前选择的 deepseek-v4.1-flash；三个合成案例均主动加载所需专项技能，九项新增技能均观察到实际 skill 调用，加载无错误 |

实际业务读工具返回隔离的固定合成资料，未接入生产写工具。评估执行三类案例、修订后的同案例复核，以及一次聚焦容量与边界的补充复核，共七次独立角色活动；没有扩大到全量业务和 UI 测试。

观察到的有效判断包括：采购清单缺失、并发不能作为飞机数量、无依据的一秒时限、旧范围与新补充需要重新审阅、云端产品不符合离线约束、无依据的大屏项、录像纯数据量 25.92 TB，以及明确假设下一主一副为 51.84 TB。

试跑同时暴露了技能文字不能保证的模型偏差，已据此进行针对性修订：

- 将已明确的工单推送、录制能力或保留期重新描述为未知：增加已知事实保持和输出前回查。
- 由材料提到机库推断必须新增采购：要求先核对客户资产、交付责任和本轮确认范围。
- 将不同的下限数字称为互斥冲突：补充包含、收紧与无解的区分。
- 把只读到的解析片段或未核验状态扩大为整份文件缺失/证据失效结论：拆开阅读范围、文本匹配、语义支持与系统状态。
- 自行展开副本或二进制单位时出现错误：增加总份数定义、字节数不变量及避免非必要换算的规则。

最后一次聚焦复核正确给出 25.92 TB 和 51.84 TB，也保留了已知工单边界；但仍输出了一段多余且不一致的二进制换算，之后补充了字节数不变量说明，未再增加付费模型复测。因此这里确认格式、可发现性及真实选用，不宣称所有业务语义和数值已经稳定通过。正式数量仍由已有测算工具与人工审阅控制；后续应使用真实长标书继续检验，不用 Skill 替代确定性校验。

本机原始验收结果保存在 /private/tmp/pbs-skill-smoke-20261021.json、对应 -recheck.json 与 -focused.json，仓库保留可迁移的合成输入及独立 expected_review 检查项，不保存密钥或原始模型内部推理。
