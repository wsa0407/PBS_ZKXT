# PBS 角色指令与共享技能审查

本轮依据：用户要求三个专业 Agent 主动选择协作路径，角色说明充分定义目标、职责、边界与能力，所有 Skills 对各角色共享并可选择加载。已有人工确认范围和成果保护继续保留。本文件记录本轮实际修订和仍需改变的运行机制，不代表双向自主协作已经全部实现。

## 设计选择

采用“共用规范 + 三份角色说明 + 一个共享技能目录”。共用规范维护业务对象、证据、人工确认与表达；角色说明维护专业目标、输入、能力、产物责任、边界、协作及完成条件；技能维护可复用的具体方法。

不采用每角色单独复制技能库，否则方法会分叉，跨职责理解也受限。不将全部技能正文常驻每个 Agent 的提示词，否则每轮加载无关操作与字段。共享名称/描述，由模型按当前任务选择加载正文，权限继续由宿主执行。

## 发现与处理

| 发现 | 实际处理 |
| --- | --- |
| 三份角色说明过短，共用指令仍像一个全能 Agent | 重写共用身份与三份角色文件，明确各自产物及停止条件 |
| 材料角色禁止编制场景，需求技能却要求抽取后接着生成场景 | 删除技能中的自动场景生成，改为按目标核查、准备交接或咨询 |
| 局部咨询可能被全文覆盖及整个项目收尾规则扩大 | 区分完整拆解、局部求证和当前角色的验收范围 |
| ★/▲ 的含义规则冲突 | 指令统一要求回查原文标记说明，区分系统审阅策略；后端硬编码仍需另行修正 |
| 产品技能描述承诺“生成 BOM”，但只有读取能力 | 改为读取产品 BOM、避免重复计量，不承诺修改共享 BOM |
| 三个技能按阶段组织，缺少可跨角色复用的方法 | 补充 pbs-evidence、pbs-clarification、pbs-collaboration，共六个共享技能 |
| 共享技能容易被理解为共享所有写权限 | 每份技能说明可读取方法与实际写权限的区别；咨询只读、人工成果保护保留 |
| 指令让 Agent 遵守权限，但协作状态未说明可咨询对象 | collaboration_state 新增 capabilities，返回当前模式的 business_tools 和 consultation_targets |
| 跨片段引用限制可能被误当客户不明确 | 区分证据表示限制和客户真实歧义，不能为适配单片段而造引用或多问客户 |

## 技能发现与调用

三个角色都经 runtime/host.mjs 调用同一个 pbsPreset，挂载 agents/pbs/skills。官方 dsh-skill-filesystem 发现直接子目录的 SKILL.md，dsh-tool-skill 先提供名称和描述，再按需加载正文。没有角色专属技能过滤，也没有 disable-model-invocation 限制。

当前 watch=false，新增/删除技能在后续宿主激活重新发现；历史已加载的正文不会被编辑自动替换。本次在无活跃任务时重启本地预览服务，使新增的能力说明接口生效。没有发起真实付费模型任务或修改已有业务成果。

## 核心验证

- 六份 SKILL.md 通过 skill-creator 的 quick_validate.py，检查 frontmatter、命名及未完成模板。
- 使用已安装的官方 dsh-skill-filesystem FileSystemSkillProvider，按实际 pbsPreset 配置分别发现与加载三个角色的目录：每个角色六个技能，十八次正文加载成功，全部允许模型选择，无解析警告。此项验证发现/加载能力，不等同于真实模型已经正确选择技能。
- 协作核心测试六项通过，覆盖人工确认、真实关联的脚本化多轮咨询、补充与写入竞态、恢复幂等、证据权限、部分范围测算。本轮在已有咨询测试中检查 capabilities 与主任务/咨询模式权限一致。
- 修改的服务与测试文件通过 ESLint，补丁通过 git diff --check。

## 尚未实现的运行机制调整

1. **自主交接和完整双向咨询**：当前仍有宿主自动材料→理解交接，咨询目标与权限仍是有限方向。需增加实际交接/投递能力、允许适当的双向咨询、处理循环依赖，并将业务推进决策移交 Agent；不能只删除方向限制或改角色文案。
2. **原文强度与重点审阅分离**：agent-adapter.mjs、旧 extract.mjs 和审核规则仍使用 ★/▲ 提升优先级。后续应将标记、已核实的要求强度、内部审阅策略分别维护，兼顾已有项目；本轮不变更数据库或历史要求强度。
3. **产品咨询证据**：产品技能可读取目录和资料，但 submit_expert_answer 的证据验证目前只接受项目材料片段。PBS 成为被咨询方时，要支持可回读的产品来源类型与版本，不能把产品事实冒充客户材料。

后续验收关注实际发起的咨询和交接、技能按需使用、证据与人工范围保护。不得只检查文档标题或用一个模型生成的角色对话冒充多 Agent 协作。
