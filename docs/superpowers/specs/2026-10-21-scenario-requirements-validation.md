# PBS 场景需求实现与验证记录

本轮实现了材料和原始需求到场景性需求、澄清及 PBS 的关联。采用现有 Node、SQLite、Vue 服务和结构化模型调用，无需 Skill 运行时。

## 已实现的业务行为

- 增加独立场景需求及工作页，记录目标、角色、条件、活动、结果、边界、推断和字段证据；支持新增、编辑、确认、归档、恢复与历史版本查看。
- 场景与原始需求多对多关联。同一条款可支撑多个需求和场景；性能、安全、交付服务、商务资质和范围外内容有独立处理去向。
- 合并、拆分保存原场景及替代关系，拒绝遗漏原关联需求，并把适用约束范围转到新场景待复核。
- 问题关联场景和字段；客户答复先形成建议，人工选择应用。涉及正式标书的潜在冲突需要记录处理依据，答复保留为可追溯来源。
- 场景上下文、约束和未解决问题传给产品检索及 PBS 生成。界面与 Excel 可沿 PBS 返回场景和客户原文。
- 保存编辑和确认是独立动作。上游变化取消相关 PBS 确认并标记复核；曾经人工确认的项保留人工处理标记，后续重生成仍保留原项。

## 数据一致性处理

数据库启动执行增量迁移。需求重抽取保留未变化内容的编号，替代结果保留历史编号。移除材料后保留来源快照，材料编号不复用。

产品资料片段按内容和所属对象保留身份。索引重建不会改变未变化证据的编号；过期资料留作历史依据，不再参与当前检索，并使相关 PBS 待复核。

场景、处理去向及答复应用使用版本检查和事务。场景生成请求完成后可幂等重放；模型执行期间项目发生变化时，旧结果不能覆盖新结果。PBS 生成与重新匹配也检查依据版本。

## 页面验证

使用独立临时数据库和仓库内森林防火模拟纪要，浏览器实际检查了：

1. 场景列表、详情、业务活动、原文证据和未解决问题展示。
2. 保存编辑后保持待确认并更新版本；单独确认后未解决问题仍保留。
3. 需求去向可编辑，保存后关联场景标记待复核，对话快捷建议同步更新。
4. 页面字段使用业务名称，原文可展开查看，当前页未产生浏览器错误日志。

浏览器演示数据是人工构造的验收样例，没有调用真实模型。它不计入模型质量基线。
