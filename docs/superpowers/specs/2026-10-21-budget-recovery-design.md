# 长材料协作的上下文与预算恢复

## 问题及选择

PBS 活动累计使用 token 达到宿主上限，原样恢复旧会话又继续携带膨胀的历史，造成重复中止。审批快照中的需求、场景证据与已读资料也被重复注入。失败提示未区分原因，恢复提示则固定声称有人工补充。

仅提高额度会掩盖重复输入；仅清空会话会丢失进行中的业务关联。本次采用范围索引、官方 dsh 压缩和持久化成果恢复的组合。

## 边界和实现计划

1. 模型只接收完整的人工确认编号索引，详情通过已有分页工具读取。数据库审批、原文证据和人工修改保留；PBS 的三层权限检查不变。
2. dsh 提前压缩会话，宿主记录正常回答和压缩摘要的用量，区分时间、步骤、token 和重复校验错误。
3. 预算中止在活动输入中持久化恢复标记。新会话先核对保存结果与待办；旧会话可审计，同一活动的幂等作用域不变。
4. 只有 token 中止且确有新保存成果时，允许一次自动续接，仍共享本轮 300 万 token、30 分钟和 36 活动上限。其他中止不自动重试。用户明确继续获得新的有界预算；保留历史用量，禁止启动时自动调用模型。
5. 失败原因直接显示。恢复只更新进度，是否有待处理补充取决于持久化收件箱。

## 核心验证

- 范围索引不漏确认编号，不修改审批快照，详细资料可回读。
- 预算原因准确，自动续接最多一次，共同预算不能被内部续接重置。
- 新会话保留操作幂等和历史用量；人工改动使 PBS 确认失效时不能继续写入。
- 原有专家咨询、人工插话、运行时关闭和业务旅程回归通过。
- 离线检查后通过原应用恢复入口继续实际失败任务，不编辑数据库或代替人批准范围。

## 自查

恢复的是任务执行，不是重新确认业务范围。额度按用户发起的一轮执行计算，历史统计不抹除。自动续接有明确次数、进展和共同预算限制；摘要是运行上下文，业务事实仍以持久化证据为准。
