# PBS 全面迁移至官方 DeepSeek Harness 的架构设计

日期：2026-10-21。状态：首版本地架构迁移已实现并验收，现有界面已接入官方 dsh。实际通过项、保留的兼容代码及未覆盖范围见[实施验收记录](2026-10-21-harness-migration-validation.md)。

## 已确认的方向

用户要求底层技术架构全面迁移至 DeepSeek 官方的 [deepseek-harness（dsh）](https://github.com/deepseek-ai/deepseek-harness)，并已确认保留现有 PBS 业务界面。

用户进一步明确：公司未来会建设基于 dsh 的统一工作台，并提供自己的 RAG。本次 PBS 是提前开发的业务 Agent，最终交付应是可安装到该工作台的 Agent 包。本地工作台与运行时接入用于开发、演示和验收；业务 Agent 不依赖这套界面的内部实现。

目标是由 dsh 统一承担模型驱动的规划、工具调用、执行结果反馈和后续调整，覆盖材料理解、原始需求抽取、澄清、场景拆分、产品匹配及 PBS 生成。业务界面继续呈现材料、需求、场景、澄清、PBS 和导出；这些视图展示业务成果与状态，不再以固定调用链驱动模型分析。

本次不是仅替换模型名称，也不是只增加错误恢复节点。已有 Workflow 主导分析的设计方向被本设计替代；既有业务对象、来源追溯和人工审核规则继续成立。

## 设计时的框架依据

已阅读官方架构、SDK、模型适配和工具注册文档：

- [架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)：Cordis 插件组合，Agent loop、工具、模型和会话均有独立接口；提供命名 profile。
- [TypeScript SDK](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/sdk/client/README.md)：通过 stdio JSON-RPC 启动独立 dsh 进程，支持会话、运行和事件订阅。
- [工具](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md)：支持参数校验与工具结果反馈，普通工具失败不要求结束整个 turn。
- [模型网关适配](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-pi-ai/README.md)：支持配置 OpenAI 兼容网关。
- [项目状态](https://github.com/deepseek-ai/deepseek-harness#developer-preview)：目前为 developer preview，公共接口可能出现不兼容变更。
- [Agent preset](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/README.md)：宿主共享 Agent loop，各 Agent 声明自己的工具、提示词与 Skills。
- [Skills](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/README.md)：可通过不同 provider 发现和加载任务指令。
- [上下文指令](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/README.md)：指令插件支持加载 `AGENTS.md`/`CLAUDE.md`；不能假定任意命名的 `Agent.MD` 会被自动加载。

文档支持上述集成方向，不代表 PBS 与 BAI 已完成兼容验证。实施的首个验证必须覆盖真实多轮工具调用，不能用普通聊天成功替代。

## 接入方式

| 方式 | 适用性 | 决定 |
| --- | --- | --- |
| 现有 Node 后端通过官方 TypeScript SDK 管理独立 dsh 进程 | 方便衔接现有服务与事件，业务工具可通过 MCP 提供 | 推荐 |
| 通过 ACP 驱动 dsh | 官方支持的自动化入口，支持会话与取消；需接入另一套协议 | 备选，SDK 验证发现阻碍时评估 |
| 扩展 dsh 官方 Web 为 PBS 工作台 | 需要迁移现有业务交互和界面 | 用户已选择保留现有界面，因此不采用 |

本地开发宿主通过官方命名 profile 启动，不复制或修改框架核心。PBS 自建 profile patch、业务提示词和工具配置，固定已验证的运行时、SDK 及相关包版本。未来由公司工作台管理 dsh 生命周期，本地 SDK 启动桥不属于必须随 PBS Agent 迁移的业务代码。

SDK 当前没有单 turn 取消方法，中止通过关闭运行时完成。因此本地开发宿主第一版按项目隔离运行时，并限制全局活跃进程与模型并发；不会在一个可被整体关闭的进程里混放不同项目的任务。公司工作台将来可以采用自己的隔离与取消实现，但必须满足相同的项目隔离和停止写入契约。

SDK 恢复持久会话并不等于恢复外部进程或自动补完业务事务。业务检查点与幂等控制由 PBS 管理。

## 目标分层

1. **工作台宿主**：本地用现有 PBS 界面，未来用公司工作台；负责交互、用户与项目身份、模型配置、预算、会话和 dsh 生命周期。
2. **可迁移 PBS Agent 包**：包含 Agent 配置、通用指令、Skills、业务策略、工具与成果契约、业务校验插件以及验收样本。
3. **dsh 运行时**：由宿主提供通用 Agent loop，通过 Agent preset 装载 PBS 能力，执行模型与工具反馈循环。
4. **业务与平台能力接口**：PBS 通过稳定接口访问材料证据、RAG、产品/BOM、成果存储和人工确认；宿主提供这些接口的具体实现。
5. **基础设施适配层**：本地使用 SQLite、现有检索和 DashScope embedding；未来接公司 RAG、业务 API、数据服务和权限系统。

PBS profile 显式配置业务工具白名单，不默认向业务 Agent 暴露通用 shell、任意 SQL、插件安装或自改代码工具。前端呈现行动、工具结果和审核依据，不依赖展示模型的内部推理文本。

最终所有业务分析模型调用都进入 dsh。应用服务和业务工具不继续私下调用旧的 `createLlm().json()`，以免形成两个规划器和两套不一致的上下文。

## 模型与向量服务

默认通过现有 BAI 网关使用用户选择的 DeepSeek 模型。dsh 的官方 DeepSeek 路由与 BAI 路由是不同配置，现有 BAI 密钥不能假设适用于 DeepSeek 官方接口。

优先验证官方 pi-ai 适配器的 OpenAI 兼容路由，验证模型标识、流式工具参数、多轮工具结果、推理模式以及代理连接。如通用适配不足，增加符合 dsh 模型接口的 PBS 网关插件，不在业务工具中添加零散兼容分支。

本地 RAG 适配器继续使用现有 DashScope embedding 服务。PBS Agent 只依赖证据检索与读取契约，不依赖 embedding 模型、向量维度、索引名称或数据库类型。未来切换公司 RAG 时替换适配器和配置，重新验证检索质量；不将向量索引作为 Agent 包的一部分搬迁。

## 面向公司工作台的可迁移交付

迁移目标是装载同一份 PBS Agent 包并绑定公司能力。仅复制几个 Markdown 文件不足以保证业务工具、数据、权限和成果仍然可用。

| 资产 | 归属与迁移方式 |
| --- | --- |
| Agent 身份、目标、边界与完成条件 | 随 Agent 包发布；使用 persona/prompt 配置，工作区规则按宿主配置加载 `AGENTS.md` |
| Skills 及其引用模板、脚本、规则 | 随 Agent 包完整发布，声明依赖与相对路径 |
| 通用 Agent loop | 由公司工作台的 dsh 提供，避免 PBS 维护一份框架分叉 |
| PBS 特有的校验、纠错策略和停止条件 | 指令、配置或插件随包发布；程序可判定的规则由工具/插件执行 |
| 工具定义、成果 schema 与错误类型 | 随包版本化；工作台通过适配器实现相同契约 |
| PBS 特有业务工具实现 | 可随包部署为插件/MCP 服务，或由公司业务服务提供兼容实现 |
| RAG、模型、用户权限、会话与基础存储 | 宿主提供，Agent 包声明所需能力，不内置地址、密钥和用户身份 |
| 项目材料、人工成果、历史会话 | 独立的数据迁移工作，不因 Agent 安装自动迁移 |
| 回归样本与评测标准 | 随包发布，在本地和公司工作台验证行为兼容 |

建议组织为一个 `agents/pbs/` 业务包，包含 `instructions/`、`skills/`、`contracts/`、`plugins/`、`evals/` 和可装载的 preset 配置。`adapters/local/` 与本地 Web/SDK 启动桥位于包外。具体目录与 manifest 字段在实现时遵循所固定 dsh 版本的实际加载契约，此处不是声明一个框架已经支持的自定义清单格式。

Agent 的业务指令与 Skills 不依赖本机绝对路径、SQLite 表名、前端 DOM 选择器、特定 HTTP 路由或某家 RAG 的返回对象；这些具体实现放在适配器中。工具名、参数、返回结构、错误语义和权限行为按版本对齐；仅对齐 MCP 传输协议并不足以实现业务兼容。

未来安装步骤为：加载 Agent 包、绑定平台能力、映射项目与知识库、运行兼容性和业务评测。上述条件满足后，迁移应只调整配置和适配器，不改 PBS 业务指令与 Skills。模型结果允许合理差异，不承诺跨模型或跨 RAG 输出逐字相同。

## 公司 RAG 的接入契约

下述接口是 PBS 需要的平台能力建议，尚未与公司工作台确定实际 API。未来公司 RAG 的接口不同，由适配器映射。

| 能力 | 输入要点 | 返回要点 |
| --- | --- | --- |
| `search_evidence` | 查询、知识域、限定文档与版本、分页/数量 | 来源 ID、版本、原文片段、定位信息和继续读取标识 |
| `read_evidence` | 来源 ID、版本、位置及受限上下文范围 | 可核对的原始内容、位置、版本和相邻片段 |
| `list_document_sections` | 文档 ID、版本、分页游标 | 完整可枚举的章节/片段目录与下一页游标 |

检索结果统一保留 `document_id`、`document_version`、`evidence_id`、原文 `text`、可用的页码/章节/位置，以及可回读的引用。全文读取与检索命中使用同一文档身份和版本；若原始资料没有页码，不伪造页码。稳定定位与版本是业务证据身份，避免绑定向量库的临时 chunk ID。

招标文件完整拆解需要可枚举、可逐段读取的文档能力。相似度 Top-K 搜索只适合定位相关内容，不能证明整份标书已经覆盖。公司 RAG 若仅提供摘要或 Top-K 接口，需要公司文档服务补充读取与目录能力，由统一适配层提供给 Agent。

项目材料与公司产品知识使用明确的知识域及文档范围。租户、用户和项目权限由宿主绑定并在服务端执行，不能由 Agent 自填参数扩大检索范围。引用失败时能回读原文，而不是重新引用一个不可溯源的生成摘要。

产品能力说明可以由 RAG 检索；产品 ID、BOM 组成、数量规则、版本和人工审核状态通过结构化业务接口查询和校验。RAG 不承担全部业务事实存储职责。

## Agent 如何完成业务

一个项目运行由一个主 Agent 负责。主 Agent 接收目标、当前成果版本、材料目录和可用工具，根据缺口选择读取、生成、校验或修复操作。第一版不要求多个角色 Agent，避免先引入额外协调复杂度。

例如“根据怀柔招标文件生成可审阅 PBS 草稿”：

1. 查看项目成果、材料结构和已处理的范围。
2. 按需阅读条款与上下文，分段形成原始需求草稿并提交校验。
3. 根据校验反馈补查引用、遗漏、数字和条件，必要时缩小处理范围重做。
4. 提出澄清问题，生成场景需求及来源映射。
5. 检索产品能力、限制和 BOM，组合适合本项目的方案，生成 PBS 草稿。
6. 查询覆盖、引用、产品约束和数量检查结果，继续修复可解决项。
7. 提交有明确剩余问题与证据的草稿；需要人工确认的业务状态由应用服务控制。

上述描述是业务目标和验收要求，不编码为只能依次执行一次的七个模型节点。Agent 可以回查、补充并迭代，但受项目范围、工具权限和运行预算约束。

解决方案属于客户项目内的自由组合成果；产品库维护产品与能力，BOM 描述产品组成，保持此前已确认的业务边界。

## 工具边界

以下为待实现的业务契约，不是 dsh 自带的工具名称。

| 工具组 | 代表能力 | 返回与约束 |
| --- | --- | --- |
| 项目状态 | 获取成果、待办、版本和运行检查点 | 返回摘要与分页入口，不把整库塞入上下文 |
| 材料与证据 | 列目录、读片段与相邻内容、检索原文 | 返回稳定来源 ID 和原文；片段引用可回溯 |
| 原始需求 | 提交草稿、查询范围覆盖、校验引用 | 返回逐项成功或错误，保留已通过项与失败项身份 |
| 场景与澄清 | 提交场景、来源关联及问题草稿 | 校验关联实际存在的需求，区分原文事实、推断和未知 |
| 产品与 BOM | 检索产品、读取能力限制及组成 | 返回真实目录身份、版本和证据，保留独立 MOCK 数据源 |
| PBS | 提交组合与明细草稿、检查覆盖和约束 | 校验需求承接、产品身份、BOM 关系及数量依据 |
| 审核与运行 | 获取问题、提交本次成果、读取预算与状态 | Agent 可以提交待审成果；人工确认及项目完成状态由业务规则决定 |

校验反馈包含错误类型、对象 ID、原因和允许的修复范围。超时、限流、输出超限、引用错误、版本冲突和凭据错误分别表达，避免仅返回一段“失败”。

材料属于分析数据。即使材料中包含命令或流程指令，也不能获得调用工具或修改权限的授权。

## 数据、一致性与恢复

- 业务数据服务是业务事实来源，本地实现为 SQLite，未来可由公司服务替换；dsh 会话保存执行与对话历史，两者通过 `project_id`、`run_id` 和 `session_id` 关联。
- 项目与运行身份由应用绑定到工具执行上下文，不能通过模型修改参数切换项目。
- 每个业务变更带接入层分配的操作身份和预期版本，重试沿用同一身份。重复工具调用返回既有结果；过期版本返回冲突，要求重新读取，避免覆盖人工修改。
- 原文与已确认的人工成果不由模型覆盖。修复产生草稿或新版本，通过现有审核机制进入正式成果。
- 批次检查点保存材料版本、已处理片段、已保存草稿和剩余问题。恢复时核对材料版本，仅续做未完成部分。
- 工具事务完成后才报告成功。若业务提交完成但会话记录尚未完成，重放同一操作身份可查询原结果，不重复入库。
- 模型预算覆盖请求次数、累计 token、运行时长和重复失败次数。达到预算时保留成果与待办，明确报告剩余工作。
- 取消和进程退出必须等待工具完成或确认中止；不能显示任务已结束却仍在后台写数据。

会话压缩后的摘要不作为条款原文或产品证据。需要依据时重新读取业务工具中的原始数据。

## 错误恢复与完成判定

工程层负责连接、限流重试、请求超时和输出预算等可确定的处理。dsh 将模型和工具执行结果纳入循环；PBS 负责反馈业务失败的具体原因。

Agent 根据反馈重新查阅原文、调整处理范围、修正草稿或补充关联。原文引用、产品存在性和数量规则必须经过工具实际校验；不能用模型文字说明代替通过记录。

对怀柔标书中当前 203 条引用未通过的初稿，目标是逐项回查并提出修复；验收不预设全部可自动通过。无法核实的内容继续进入人工审阅，不伪造依据。

运行结束状态区分：草稿已就绪、需要人工输入、预算耗尽、已取消、运行失败。框架 idle 或模型说“完成”都不能直接标记整个业务项目已完成。

## 实施顺序与验证

目标架构一次对齐，代码按可验证的增量迁移。

1. **运行时与网关验证**：固定版本，建立可迁移 Agent preset 与本地宿主，启动独立 dsh profile，通过 BAI 完成真实工具调用、一次工具失败后的策略调整和会话恢复。核对进程退出、代理和事件格式。此阶段不修改现有业务成果。
2. **业务工具与数据契约**：拆出材料检索、草稿写入及校验服务，建立项目隔离、幂等、版本冲突和检查点。定义宿主能力接口并实现本地适配器，通过 MCP 暴露并测试实际组合。
3. **全业务分析迁移**：依次迁移材料理解、需求、场景、澄清、产品文档解析、PBS 及重匹配；所有业务分析统一通过 dsh。
