# PBS 全面迁移至官方 DeepSeek Harness 的架构设计

日期：2026-10-21。状态：待评审，尚未安装或接入运行时。

## 已确认的方向

用户要求底层技术架构全面迁移至 DeepSeek 官方的 [deepseek-harness（dsh）](https://github.com/deepseek-ai/deepseek-harness)，并已确认保留现有 PBS 业务界面。

目标是由 dsh 统一承担模型驱动的规划、工具调用、执行结果反馈和后续调整，覆盖材料理解、原始需求抽取、澄清、场景拆分、产品匹配及 PBS 生成。业务界面继续呈现材料、需求、场景、澄清、PBS 和导出；这些视图展示业务成果与状态，不再以固定调用链驱动模型分析。

本次不是仅替换模型名称，也不是只增加错误恢复节点。已有 Workflow 主导分析的设计方向被本设计替代；既有业务对象、来源追溯和人工审核规则继续成立。

## 框架依据与尚未验证的能力

已阅读官方架构、SDK、模型适配和工具注册文档：

- [架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)：Cordis 插件组合，Agent loop、工具、模型和会话均有独立接口；提供命名 profile。
- [TypeScript SDK](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/sdk/client/README.md)：通过 stdio JSON-RPC 启动独立 dsh 进程，支持会话、运行和事件订阅。
- [工具](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md)：支持参数校验与工具结果反馈，普通工具失败不要求结束整个 turn。
- [模型网关适配](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-pi-ai/README.md)：支持配置 OpenAI 兼容网关。
- [项目状态](https://github.com/deepseek-ai/deepseek-harness#developer-preview)：目前为 developer preview，公共接口可能出现不兼容变更。

文档支持上述集成方向，不代表 PBS 与 BAI 已完成兼容验证。实施的首个验证必须覆盖真实多轮工具调用，不能用普通聊天成功替代。

## 接入方式

| 方式 | 适用性 | 决定 |
| --- | --- | --- |
| 现有 Node 后端通过官方 TypeScript SDK 管理独立 dsh 进程 | 方便衔接现有服务与事件，业务工具可通过 MCP 提供 | 推荐 |
| 通过 ACP 驱动 dsh | 官方支持的自动化入口，支持会话与取消；需接入另一套协议 | 备选，SDK 验证发现阻碍时评估 |
| 扩展 dsh 官方 Web 为 PBS 工作台 | 需要迁移现有业务交互和界面 | 用户已选择保留现有界面，因此不采用 |

通过官方命名 profile 启动，不复制或修改框架核心。PBS 自建 profile patch、业务提示词和工具配置，固定已验证的运行时、SDK 及相关包版本。

SDK 当前没有单 turn 取消方法，中止通过关闭运行时完成。因此第一版按项目隔离运行时，并限制全局活跃进程与模型并发；不会在一个可被整体关闭的进程里混放不同项目的任务。

SDK 恢复持久会话并不等于恢复外部进程或自动补完业务事务。业务检查点与幂等控制由 PBS 管理。

## 目标分层

1. **PBS 业务界面**：展示成果、工具执行进度、修复情况、待审核事项及人工确认入口。
2. **PBS 应用服务**：承接现有 HTTP API，管理项目、运行身份、权限、会话映射、业务确认及前端事件投影。
3. **dsh 运行时**：通过 SDK 接收目标和上下文，选择业务工具，读取执行反馈并调整下一步；会话日志由框架管理。
4. **PBS 业务工具服务**：以 MCP 暴露小粒度能力，参数、返回结构、写入校验与幂等性有明确契约。
5. **业务数据与行业配置**：SQLite 中保存正式业务对象、版本和证据；领域规则、产品目录、BOM、MOCK 数据和评测样本独立维护。

PBS profile 显式配置业务工具白名单，不默认向业务 Agent 暴露通用 shell、任意 SQL、插件安装或自改代码工具。前端呈现行动、工具结果和审核依据，不依赖展示模型的内部推理文本。

最终所有业务分析模型调用都进入 dsh。应用服务和业务工具不继续私下调用旧的 `createLlm().json()`，以免形成两个规划器和两套不一致的上下文。

## 模型与向量服务

默认通过现有 BAI 网关使用用户选择的 DeepSeek 模型。dsh 的官方 DeepSeek 路由与 BAI 路由是不同配置，现有 BAI 密钥不能假设适用于 DeepSeek 官方接口。

优先验证官方 pi-ai 适配器的 OpenAI 兼容路由，验证模型标识、流式工具参数、多轮工具结果、推理模式以及代理连接。如通用适配不足，增加符合 dsh 模型接口的 PBS 网关插件，不在业务工具中添加零散兼容分支。

向量检索继续使用现有 DashScope embedding 服务，由检索工具调用。模型推理和 embedding 分别配置、分别验证；全面迁移指 Agent 执行基础设施的统一。

## Agent 如何完成业务

一个项目运行由一个主 Agent 负责。主 Agent 接收目标、当前成果版本、材料目录和可用工具，根据缺口选择读取、生成、校验或修复操作。第一版不要求多个角色 Agent，避免先引入额外协调复杂度。

例如“根据怀柔招标文件生成可审阅 PBS 草稿”：

1. 查看项目成果、材料结构和已处理的范围。
2. 按需阅读条款与上下文，分段形成原始需求草稿并提交校验。
3. 根据校验反馈补查引用、遗漏、数字和条件，必要时缩小处理范围重做。
4. 提出澄清问题，生成场景需求及来源映射。
5. 检索产品能力、限制和 BOM，组合适合本项目的方案，生成 PBS 草稿。
6. 查询覆盖、引用、产品约束和数量检查结果，继续修复可解决项。
7. 提交有明确剩余问题与证据的草稿；需要人工确认的业务状态由应用服务控制。

上述描述是业务目标和验收要求，不编码为只能依次执行一次的七个模型节点。Agent 可以回查、补充并迭代，但受项目范围、工具权限和运行预算约束。

解决方案属于客户项目内的自由组合成果；产品库维护产品与能力，BOM 描述产品组成，保持此前已确认的业务边界。

## 工具边界

以下为待实现的业务契约，不是 dsh 自带的工具名称。

| 工具组 | 代表能力 | 返回与约束 |
| --- | --- | --- |
| 项目状态 | 获取成果、待办、版本和运行检查点 | 返回摘要与分页入口，不把整库塞入上下文 |
| 材料与证据 | 列目录、读片段与相邻内容、检索原文 | 返回稳定来源 ID 和原文；片段引用可回溯 |
| 原始需求 | 提交草稿、查询范围覆盖、校验引用 | 返回逐项成功或错误，保留已通过项与失败项身份 |
| 场景与澄清 | 提交场景、来源关联及问题草稿 | 校验关联实际存在的需求，区分原文事实、推断和未知 |
| 产品与 BOM | 检索产品、读取能力限制及组成 | 返回真实目录身份、版本和证据，保留独立 MOCK 数据源 |
| PBS | 提交组合与明细草稿、检查覆盖和约束 | 校验需求承接、产品身份、BOM 关系及数量依据 |
| 审核与运行 | 获取问题、提交本次成果、读取预算与状态 | Agent 可以提交待审成果；人工确认及项目完成状态由业务规则决定 |

校验反馈包含错误类型、对象 ID、原因和允许的修复范围。超时、限流、输出超限、引用错误、版本冲突和凭据错误分别表达，避免仅返回一段“失败”。

材料属于分析数据。即使材料中包含命令或流程指令，也不能获得调用工具或修改权限的授权。

## 数据、一致性与恢复

- SQLite 是业务事实来源；dsh 会话保存执行与对话历史，两者通过 `project_id`、`run_id` 和 `session_id` 关联。
- 项目与运行身份由应用绑定到工具执行上下文，不能通过模型修改参数切换项目。
- 每个业务变更带接入层分配的操作身份和预期版本，重试沿用同一身份。重复工具调用返回既有结果；过期版本返回冲突，要求重新读取，避免覆盖人工修改。
- 原文与已确认的人工成果不由模型覆盖。修复产生草稿或新版本，通过现有审核机制进入正式成果。
- 批次检查点保存材料版本、已处理片段、已保存草稿和剩余问题。恢复时核对材料版本，仅续做未完成部分。
- 工具事务完成后才报告成功。若业务提交完成但会话记录尚未完成，重放同一操作身份可查询原结果，不重复入库。
- 模型预算覆盖请求次数、累计 token、运行时长和重复失败次数。达到预算时保留成果与待办，明确报告剩余工作。
- 取消和进程退出必须等待工具完成或确认中止；不能显示任务已结束却仍在后台写数据。

会话压缩后的摘要不作为条款原文或产品证据。需要依据时重新读取业务工具中的原始数据。

## 错误恢复与完成判定

工程层负责连接、限流重试、请求超时和输出预算等可确定的处理。dsh 将模型和工具执行结果纳入循环；PBS 负责反馈业务失败的具体原因。

Agent 根据反馈重新查阅原文、调整处理范围、修正草稿或补充关联。原文引用、产品存在性和数量规则必须经过工具实际校验；不能用模型文字说明代替通过记录。

对怀柔标书中当前 203 条引用未通过的初稿，目标是逐项回查并提出修复；验收不预设全部可自动通过。无法核实的内容继续进入人工审阅，不伪造依据。

运行结束状态区分：草稿已就绪、需要人工输入、预算耗尽、已取消、运行失败。框架 idle 或模型说“完成”都不能直接标记整个业务项目已完成。

## 当前模块如何迁移

| 当前模块 | 迁移目标 |
| --- | --- |
| `server/chat.mjs` 的一次意图识别与 actions 执行 | 由 dsh turn/tool 循环接管；应用层负责投递消息与展示事件 |
| `engine/llm.mjs`、`lib/bai_client.mjs` 的业务模型调用 | 迁入 dsh 模型路由；最终移除旧业务分析调用路径 |

| `engine/extract.mjs`、`scenario.mjs`、`clarify.mjs` 等模型步骤 | 分离为 Agent 指令与工具校验逻辑，模型分析由 dsh 承担 |
| `engine/pbs.mjs` 的模型规划与规则混合逻辑 | 模型规划迁入 Agent，产品约束、覆盖与数量计算保留为业务工具 |

| `repo.mjs`、数据库、目录、引用与版本规则 | 作为业务层演进，保持人工成果及审计一致性 |
| 现有前端工作台与导出 | 衔接新运行状态，继续展示和操作原有业务对象 |

禁止将原有 `analyzeMaterials`、`generateProjectPbs` 整体包成工具后仍在内部跑原固定 LLM 调用链，并把它作为全面迁移的完成状态。过渡实现可以按阶段交付，但须明确标记尚未迁移的路径。

## 实施顺序与验证

目标架构一次对齐，代码按可验证的增量迁移。

1. **运行时与网关验证**：固定版本，启动独立 dsh profile，通过 BAI 完成真实工具调用、一次工具失败后的策略调整和会话恢复。核对进程退出、代理和事件格式。此阶段不修改现有业务成果。
2. **业务工具与数据契约**：拆出材料检索、草稿写入及校验服务，建立项目隔离、幂等、版本冲突和检查点。通过 MCP 暴露并测试实际组合。
3. **全业务分析迁移**：依次迁移材料理解、需求、场景、澄清、产品文档解析、PBS 及重匹配；所有业务分析统一通过 dsh。
4. **前端接入与历史兼容**：现有操作入口投递 Agent 目标，事件驱动进度与结果；保留历史业务数据及已确认内容，新会话从业务现状建立上下文，不伪造历史工具轨迹。
5. **完整验收与清理**：以怀柔标书及已有验收案例验证完整链路和故障恢复，通过后删除旧执行分支及不再使用的依赖。

验收包含：真实框架组合运行、多轮工具调用、失败反馈与策略变化、重复操作无重复数据、跨项目隔离、任务恢复、人工修改保护、材料提示注入、引用校验、场景与条款映射、产品/BOM 约束、取消后无迟到写入，以及实际模型调用记录。

使用同一份怀柔标书记录迁移前后的覆盖率、引用通过率、人工待审项、运行时长与 token 成本。980 条初稿与 777 条引用校验通过是现有运行的基线记录，不将生成数量相同作为验收条件，也不以数量增加代表质量提高。

## 评审结论所需范围

已确认：使用官方 dsh，保留 PBS 界面，覆盖整条业务链。

本设计建议确认的工程边界：官方 SDK 管理项目隔离的 dsh 运行时，PBS MCP 工具承接业务服务，SQLite 维护业务事实，dsh 管理 Agent 执行与会话；BAI 多轮工具兼容为首个实测关口。
