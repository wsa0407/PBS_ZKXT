# 需求理解工作区调整

用户已在会话中确认方案并授权实施。本轮范围：材料录入简化、需求/场景/澄清三个关联视图、统一 Agent 分析目标；PBS 页面和产品组合逻辑保持现状。

## 设计

- 一级导航为材料、需求理解、PBS、导出。需求理解内有需求条目、业务场景、待澄清事项；兼容旧需求/场景/澄清深链接。
- 上传文件或粘贴原文，可附标题和自由说明。文件名自动作为默认标题，不要求选择材料类型。材料性质按内容辅助识别，未知时保留为其他材料；说明单独保存，不混入可引用的原文。
- 需求下展示关联问题并提供原地答复处理入口。描述审核状态与澄清状态分别显示；无关联需求或场景的问题可作为待判断事项保留。
- 业务场景展现客户目标、活动、关联要求和未解决问题。允许主体明确但仍有细节待澄清的需求形成场景草稿；确认不代替答复。
- 统一“理解材料”目标，由现有 dsh loop 调用需求、场景和问题工具，保留人工成果。材料说明是上下文，不构成可伪造引用；不自动生成 PBS，不自动确认业务内容。
- 客户答复沿用已有分析、审阅、采纳和下游复核流程。后台保留独立业务对象，不迁移或合并历史记录。

## 实施顺序

1. 简化材料组件，保存说明并接入证据目录。
2. 建立统一工作区和兼容导航，接入需求内澄清、双状态及关联定位。
3. 合并分析目标、快捷入口及 Agent/Skills 规则。
4. 聚焦验证材料原文/说明隔离、统一目标与人工保护、答复采纳和关联导航；进行模板/静态检查及页面核验。

不增加大规模测试或完整标书重跑。视觉和低风险文案通过实际页面核验。

## 实施与核心验收

已实现以上范围。材料说明沿用材料 meta 保存，没有迁移历史数据；新路由为 `understanding/requirements`、`understanding/scenarios`、`understanding/questions`，旧入口继续可用。

- 修改文件的 ESLint 与 Vue 模板编译通过。
- 仅执行5个核心自动检查：无类型材料录入与原文隔离、统一导航及双状态、人工需求保护、答复变更采纳、过期/无依据答复拒绝；全部通过。没有运行全量回归或完整标书测试。
- 一次真实 dsh 核心流程验证，合成项目 `mvh1rgg3sqp6`：得到3条需求、1个业务场景、5项待澄清，未生成PBS、未自动确认，既有人工需求的内容和审核状态保留。新模型需求引用通过校验。
- 合成项目中人工需求没有原文引用，Agent保留该人工记录，并将相应1个原文片段留为待核验，没有虚报全部覆盖。
- 页面核验：材料页无类型选择；三个视图可切换；需求下可打开关联问题并进入答复录入；已确认描述仍显示待澄清；场景可定位问题，问题可回到需求及高亮原文。
- PBS组件与产品组合逻辑未修改。
