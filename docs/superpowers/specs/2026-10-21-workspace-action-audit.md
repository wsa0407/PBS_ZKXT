# 工作区按钮与业务状态核查

本轮根据用户对“每条需求都有澄清按钮”的反馈，核查材料、需求、场景、澄清、PBS、导出、项目方案、产品与 BOM，以及聊天和人工范围确认中的按钮条件、接口调用和跳转对象。

## 交互规则

- 需求描述审阅、澄清处理、PBS 输入范围确认分别记录。正常需求不默认带一个澄清动作，也不反复显示“暂无澄清”。
- 查看是导航，录入和采纳是业务操作；文案必须说明实际动作。有明确关联问题才提供关联入口，不用默认跳转冒充定位成功。
- 结束态不再提供进行态操作；可恢复的对象给出符合实际状态的恢复动作。按钮不能将失效选择变成有效确认。
- 数据不足时不能启动无效保存；正在启动的操作避免重复提交。任务进度沿用上一轮的单行展示。
- 工作区按钮表达用户的明确操作意图，不重新规定专家间的固定执行流程。

## 发现与处理

| 区域 | 原问题 | 修正 |
| --- | --- | --- |
| 需求列表 | 每行都有“澄清”，同一问题还有多处重复入口 | 操作列保留确认描述、修改、删除；仅实际存在待处理关联问题时显示一个“查看关联问题”入口 |
| 需求定位 | 无原文的需求被定位时误开澄清抽屉 | 定位并突出对应需求行；原文仅由来源入口打开 |
| 原文查看 | 用对象身份寻找快照位置，可能显示错误的上下文 | 用稳定来源编号定位；没有可读来源时不显示无效按钮，历史材料可读保留片段 |
| 批量确认 | 前端保留的旧选择可能已删除或被筛掉 | 只提交当前可见待审选择；后台原子校验，已删除需求不能被批量确认隐式恢复 |
| 问题处理 | 已处理项仍有通用“处理”入口或指定负责人操作 | 已处理项查看记录；只有待处理、待答复、答复待采纳状态允许相应操作 |
| 暂存问题 | 恢复后丢失已有答复的待审状态 | 有答复及建议时恢复为“答复待采纳”；不能通过旧按钮重开已处理问题 |
| 答复建议 | 选中了与正式条款冲突的建议，但处理依据为空也能点击采纳 | 缺处理依据时禁止采纳；未选择变更时仍明确提示“记录不变更” |
| 需求理解 | “继续理解与完善”仍发送材料理解指令；人工需求无材料时入口不可用 | 待处理材料调用材料理解，已有需求调用需求/场景整理；无内容不显示空操作 |
| 场景 | 无名称、无关联需求也能提交；每个详情有通用澄清创建入口 | 必要输入齐全才保存；新增问题集中到待澄清事项页，仍可关联场景字段 |
| 场景历史 | 已处理问题仍显示“处理此项澄清”；归档详情缺恢复入口 | 链接按问题状态显示查看记录、审阅建议等；归档详情提供恢复为待审阅 |
| PBS 输入确认 | 已处理问题被错误计为待澄清；选场景未包含关联需求仍能提交 | 修正持久化状态判定；显示相关/项目级待办；补入有效关联需求，缺失或已删除关联明确提示并禁止提交 |
| 确认加载 | 请求失败后仍显示“正在读取” | 加载失败有重新读取入口；提交中不能重复确认或改变勾选 |
| 材料与 PBS 启动 | 重复点击可能再次提交任务；所有任务都称“正在处理材料” | 启动期间锁定重复请求；保留按钮真实意图，由聊天区域显示实际进度 |
| 聊天恢复 | 历史失败气泡永久保留“继续处理”按钮 | 只在当前任务确实可恢复时提供统一恢复入口 |
| 导出检查 | 无关联对象或场景/问题引用都默认跳到 PBS | 解析实际需求、场景、问题、PBS 或原文；没有可定位目标时不显示假入口，通用问题导航至相应工作区 |
| 产品目录 | 已归档产品仍显示“归档”与上传手册 | 已归档产品改为恢复匹配；保留编辑，上传入口限启用产品 |
| 产品 BOM | 已有 BOM 的产品还能新增重复 BOM，必填信息未填即可保存 | 新建仅选择尚无 BOM 的启用产品，编辑保留当前产品；必填信息完整才可保存 |

## 核查后保留

- 项目新建、打开和删除对应真实操作；删除仍明确提示影响范围。
- 需求、场景及 PBS 的人工编辑和描述确认继续保留，不把描述确认当作解决澄清。
- 项目方案按客户自由组合，预览、保存 BOM 版本与编辑方案各自承担不同动作，不合并为产品库方案。
- 导出前检查和草稿导出保留；“本轮完成”仍只是人工整理状态，不代表业务验收。
- 产品手册采纳、Excel 导入和 JSON 预览导入保留各自的明确作用，不隐藏用户要求的目录维护能力。

## 核心验证

15 项定向检查通过，覆盖需求与澄清独立状态、问题恢复、已处理问题计数、失效批量确认的原子保护、场景关联确认条件、动作选择、检查项导航和既有协作权限。Vue 模板编译、修改文件 ESLint 和 diff 检查通过。本轮未做浏览器视觉验收，也未新增付费模型调用；测试使用隔离数据。
